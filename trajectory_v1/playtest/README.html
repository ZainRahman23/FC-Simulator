Frozen shooting foundation

The current approved charge controller is Laces-only. This sandbox preserves that scope; it introduces no alternate Finesse or curve input. It imports byte-identical SHOT-CHARGE-1.3, BALL-SHOT-1.2 and ball-physics modules from the existing review snapshot. The foundation includes the existing spin, drag, turf response and fixed 240 Hz substeps. CURVE-1.1 source is unchanged.

Holds up to 40 ms retain the 40% weak-shot floor; red begins at 310 ms; speed reaches its capability ceiling at 450 ms. Continued hold increases the requested apex without adding speed. The original pre-contact physical apex solver determines elevation. No goal-height targeting or post-launch corrections are introduced.

All movement is deliberately simplified. Ball possession is a fixed 0.42 m forward / 0.16 m right offset. On contact the initial physical ball is stationary, with zero spin and identity orientation, before the approved launch is applied. Movement velocity adds no new context modifier. The player root position, not the ball's foot offset, selects the zone.

Ideal and actual shots

The worker resolves one ideal launch using the original charge/apex resolver. It runs that launch in a private copy of the same physical world to obtain the ideal trace and exact goal-plane crossing. This trace is a diagnostic only; it cannot collide with the live ball or any scene object.

The actual action preserves the ideal velocity magnitude and exact world spin. Only the seeded horizontal and elevation execution errors change its launch direction. One actual BallWorld is then stepped live at 1/60 s with four substeps. Rendering reads its snapshots; it does not replay a fabricated or interpolated path, steer toward the target, or resample errors after launch.

The goal frame/net and shooter are visual references, with no collision shapes. Turf remains physical in both worlds. This keeps the comparison about execution at a common plane, without post impacts or saves changing the meaning of the markers.

The fixed goal plane extends infinitely beyond posts and bar. Gold IDEAL + and mint ACTUAL × markers show both physical intersections. A white line joins them. The separate plane view fits both points, including high/wide misses, with equal horizontal/vertical metre scale. Main-view edge labels preserve off-screen markers. If a trajectory stops or fails to cross within the 12-second observation window, the lab reports that instead of inventing a plane intersection. Ground bounces remain physical and are not smoothed. When no plane crossing exists, the behind-player view labels the observed rest or 12-second endpoint separately; those endpoints are not reported as goal-plane intersections.

Locked draws and determinism

Normal shots advance a semantic draw event ID. Lock execution draw reuses the latest standardized horizontal and elevation draw. Repeat last input reuses the original position, aim and hold but reads current attributes. New random shot repeats that input with a fresh event key, and updates the locked key when locking is enabled. Changing the seed intentionally changes the draw.

Ratings, position, hold duration and controller are excluded from this key. Each actual launch has a unique receipt ID separately from its reusable draw event ID. The audit records both. Fixed input, state, seed and draw ID produce identical physical results. Render frame rate does not change physics step size.
