B. What the calibration environment measures

The explorer supplies independent Finishing, Long Shots and Shot Power controls, archetype buttons, click and keyboard position selection, exact coordinates, reference positions, target height/side selection, and a spatial effective-accuracy overlay. It reports distance to goal centre, absolute bearing from the centreline, visible goal opening, weights, effective accuracy, angular and physical spread. Four targets are explicit ball-centre points: centre [0,1.22], bottom corner [±3.41,0.25], middle corner [±3.41,1.22], top corner [±3.41,2.19], measured laterally from goal centre and vertically above turf.

Two modes are deliberately distinguished. “Matched-speed target study” uses the frozen capability ceiling at the selected speed fraction and solves only initial elevation in a private pre-contact physical preview. It selects the first natural low-arc solution. This controlled laboratory solve is necessary to hold speed and target fixed while changing distance. It is not the approved charge trajectory. “Approved charge launch” calls the unchanged SHOT-CHARGE-1.3 resolver at the selected hold and physical origin; its gold point is the ideal charge trajectory and its white cross is the intended target. It does not force the charge trajectory to hit that target.

Both modes perform one physical launch. The ball receives no steering, target attraction, spline, post-launch spin change or artificial miss roll. Laces is the calibrated family here, with fixed clean context and unchanged family spin. The lab rotates the complete canonical shot frame to the chosen field heading; it does not remove the resolver’s ±75° local-aim guard. Other shot families require their own compatibility checks before deployment.

The goal-plane view extends outside both posts and above the bar. It shows central 50/90/99% angular probability sets mapped through the frozen physical ball, plus the complete mapped angular support. A contour can overlap after a bounce: it then represents a mapped set of angular executions, not a simple spatial confidence oval. Colour is relative to each field’s own peak. These are execution distributions, never scoring probabilities.

G. Proposed deterministic execution contract

This contract is implemented only as a reference helper in this lab. No gameplay code imports it. Four semantic uniform draws create two independent bounded triangular errors.

keyArray = [
  "shot-accuracy-v1",
  matchSeed,              // canonical decimal string, no leading zeroes
  shooterId,              // immutable stable identifier
  stableShotEventId,      // assigned when the logical shot intent is accepted
  axis,                  // "horizontal" or "elevation"
  drawIndex              // integer 0 or 1
]
keyBytes = UTF-8(JSON.stringify(keyArray))
digest = SHA-256(keyBytes)
k = unsigned integer encoded by the first 13 hex digits (52 bits)
U = (k + 0.5) / 2^52      // strictly between zero and one

ZH = sqrt(6) × (UH0 − UH1)
ZV = sqrt(6) × (UV0 − UV1)
errorYawDegrees = finalSigmaH × ZH
errorElevationDegrees = finalSigmaV × ZV

Use ASCII stable IDs in the accepted input contract and JSON’s exact compact array encoding; reject malformed/missing IDs. There is no global RNG cursor. The standardised draws have mean zero, unit variance and support [−√6,+√6]. Each axis has independent keys. The continuous product density in normalized bounded coordinates is (1−|u|)(1−|v|). The 52-bit representation discretizes that law at machine precision without admitting U = 0 or U = 1.

The key excludes attributes, position, Shot Power, hold duration, target, animation state, timing of contact and controller type. Changing them scales or physically projects the same standardized errors for the same logical shot. The stable event ID must not be derived from a tick, release time, mutable global decision counter, or the attributes. A per-shooter accepted-intent ordinal is suitable if assigned before hold/animation differences; cancellations retain their IDs and do not shift other shooters’ draws. Counterfactual runs with divergent decision trees require explicit pairing of logical shot IDs, not an assumption that every later ordinal still refers to the same event.

After approval, create a shared shooting-only module with pure classifyShootingZone, resolveEffectiveAccuracy, resolveAccuracySigma, sampleKeyedAccuracy, and applyShotAccuracy functions, plus ShotIntent, IdealShotLaunch, AccuracyContext and AccuracyAudit structures. The lab’s geometry/model/RNG helpers are reference implementations, not production imports. Centralize authoritative pitch geometry instead of parsing renderer source at runtime.

Assign the stable event ID when human or AI intent is accepted. At the final pre-contact preparation stage, snapshot authoritative shooter position and attributes, obtain the ideal launch from the approved resolver, classify and perturb once, then schedule the resulting physical action. If launch preparation happens earlier, revalidate the position snapshot at contact; rebuild using the same event ID if the approved controller permits it, or cancel. Never resample merely because contact timing or animation changed. Do not put accuracy logic inside BallWorld.launch or receiving/first-touch code.

Human / AI parity

Both controller types provide the same semantic intent fields to the same execution wrapper. Controller type may be recorded for auditing but is excluded from the RNG key and all accuracy mathematics. Human/AI fixtures with the same actor, event ID, position, attributes and ideal launch must yield bit-identical accuracy audit and launch vectors. AI aim selection may differ intentionally; AI receives no accuracy bypass, goal-attraction correction or favorable resampling.

  1. Exact box and ellipse boundary cases, both attack directions, mirrored lateral positions, penalty spot, six-yard corners, wide byline, and fractional mixed values.

Numerical limits and football sanity review

EXPECTED CONSEQUENCE · DISCRETE ZONES

Specialists have sharp accuracy cliffs; the central front-line apex jumps directly between Finishing and Long Shots. Balanced ratings have no attribute cliff. The locked ellipse makes most wide-byline shots Finishing, while near-side box edges remain Mixed. These are the chosen geometry’s consequences.

EXPECTED CONSEQUENCE · PHYSICAL SUPPORT

Low targets and poor ratings can include early turf contacts, folds and non-crossing trajectories. The lab includes frozen turf physics and adds overlapping density branches. Projections are observed until crossing, rest or 12 seconds. Mesh cells without complete plane projection are reported separately, never discarded and renormalized as if all executions reached the goal.

NUMERICAL LIMIT · DRAWING APPROXIMATION

Interactive fields use a 21 × 21 angular grid; the documented distance study uses 25 × 25. Angular mass integration per triangle is exact for the piecewise quadratic product density. The physical map between sampled nodes is interpolated. The three validation scenarios’ off-grid probes found a maximum difference of 13.92 mm, including a bottom-target turf transition. This is a spot-check result, not a global error bound. Near a contact discontinuity, the picture is a mesh approximation; production execution must run the actual ball, never the interpolated display field. Node-sampled support extrema are estimates, not a proof of exact continuous extrema.

IMPLEMENTATION GAP · NOT A ZONE BUG

The current approved physical lab and legacy AI/match paths are not unified. The legacy paths contain earlier spatial error and statistical outcomes. A naive added accuracy layer would double-count error. The proposed integration must establish a shared execution seam first; none of those source paths has been modified here.
