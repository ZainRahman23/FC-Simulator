DRIBBLE-1 — PHYSICS-BASED FOOTBALL DRIBBLING V1
TURN-1.2 is now owner-approved, frozen and published.
Frozen locomotion baseline:
- branch: prototype/turn-1
- freeze tag: locomotion-turn12-baseline-1
- final frozen commit: 2129ca04a6f4efd69b3b8a9faca990de5ce3ef07
- handoff: review_artifacts/turn1/turn12/TURN12_HANDOFF.md
Do not reopen locomotion development.
The next mission is DRIBBLE-1: build Touchline's first complete physics-based dribbling system.
This should be a real implementation with a long runway, not an architecture proposal.
1. PRIMARY PRODUCT GOAL
Build a player who can:
JOG / RUN / SPRINT
while controlling the authoritative physical ball through repeated real touches, and can:
curve → cut → turn → accelerate
while taking the ball with him.
The target is not hyper-realistic biomechanics.
The target is:
responsive, readable football dribbling built on real physical ball motion and the frozen TURN-1.2 foot/locomotion system.

The ball must visibly separate from the player's foot.
There is no invisible possession tether.
2. FIRST — RECONSTRUCT THE LATEST BALL WORK
Another agent has been developing BALL-PHYS / BALL-FEEL in parallel.
Before implementing DRIBBLE-1:
- inspect repository history;
- inspect current branches;
- inspect the project chronicle/handoffs;
- locate the newest BALL-PHYS / BALL-FEEL work;
- reconstruct its architecture and current status.
Important known lineage includes:
- BALL-PHYS-1;
- BALL-FEEL-1;
- BALL-FEEL-1.1;
- BALL-FEEL-1.2;
- BALL-FEEL-1.3;
- current reference-calibration work if it has subsequently landed.
Use the newest actual repository state, not this prompt, if they conflict.
Do not reinvent the physical ball.
3. DO NOT WAIT FOR PERFECT BALL CALIBRATION
If the newest ground-ball calibration is still on another local branch or not yet frozen:
reconstruct the latest usable BALL-PHYS interface and build DRIBBLE-1 so ball parameters can be updated cleanly afterward.
Do not spend this mission tuning:
- pass speed;
- through-ball weighting;
- curve;
- shot speed;
- turf coefficients.
DRIBBLE-1 should consume the physical ball system, not own global BALL-FEEL.
4. FUNDAMENTAL AUTHORITY CONTRACT
Preserve Touchline's core architecture:
Simulation decides what happens. Presentation/animation explains what happened.

Do not let presentation RNG or animation accidents determine authoritative football outcomes.
For DRIBBLE-1, distinguish:
PLAYER LOCOMOTION INTENT
Simulation/gameplay owns:
- desired movement direction;
- desired movement speed;
- action intent;
- contextual dribble intent.
TURN-1.2
Resolves the locomotion realization:
- stride phase;
- stance;
- plant foot;
- foot trajectories;
- foot prediction;
- cut/pivot/reversal realization.
DRIBBLE RESOLVER
Resolves:
- whether/when a deliberate touch should occur;
- which foot/boot region should make it;
- intended ball separation/direction;
- desired touch strength.
BALL-PHYS
Owns the ball after the touch.
5. NO BALL TETHER
Hard requirement:
Do NOT:
- parent the ball to the foot;
- lerp it beside the player;
- constrain it to a dribble socket;
- teleport it into stride;
- continuously attract it toward the player;
- secretly correct its position every frame.
Between touches:
the ball is free.

It rolls, skips, slows, collides and can be intercepted.
6. DELIBERATE TOUCHES NEED NOT DERIVE POWER FROM LEG PHYSICS
Preserve the ball architecture we've chosen for passes/shots.
A deliberate dribble touch does NOT need to calculate its launch solely from the literal rigidbody impulse generated by animated boot velocity.
Instead:
simulation + attributes + action context
may resolve the desired touch launch state.
The foot animation/contact must visually align with that event.
At the authoritative contact moment, apply the resolved physical ball state/impulse once.
Then:
physics owns the ball.
No double impulse.
7. BUT TEST THE THREE TOUCH ARCHITECTURES
Before committing completely, perform a focused comparison using identical TURN-1.2 locomotion:
A — PURE PHYSICAL FOOT CONTACT
Boot rigidbody/contact alone determines ball impulse.
B — RESOLVED TOUCH
Gameplay resolver determines the launch state at aligned foot contact.
C — BOUNDED HYBRID
Resolver determines the intended launch envelope, while actual foot contact/geometry provides bounded adjustment.
Compare them.
My prior expectation is that B or C will be preferable, but do not assume the verdict.
Judge:
- responsiveness;
- repeatability;
- visual contact;
- ball separation;
- controllability;
- robustness during cuts;
- compatibility with collisions.
8. START WITH STRAIGHT DRIBBLING
Do not start with tricks or 180° turns.
First solve:
JOG straight
then:
RUN straight
then:
SPRINT straight.
Required lifecycle:
player approaches ball
→ foot makes deliberate touch
→ ball physically separates
→ player runs after it
→ appropriate next foot reaches it
→ next deliberate touch
→ repeat.
At 1× it must read as dribbling, not ball attachment.
9. TOUCH DISTANCE MUST SCALE WITH SPEED
Do not use one fixed dribble separation.
Broad desired character:
WALK/JOG
close control.
Frequent, smaller touches.
RUN
larger touches.
Ball clearly moves ahead of the player.
SPRINT
significantly larger touches into space.
Player actually chases the ball between contacts.
Exact values should emerge from testing.
10. TOUCH TIMING SHOULD COME FROM REAL FOOT OPPORTUNITIES
Use TURN-1.2's:
- foot state;
- stance timing;
- swing trajectories;
- t1Predict / current equivalent;
- plant timing.
Do not fire arbitrary touches every N milliseconds.
Determine which upcoming foot trajectory provides a plausible contact opportunity.
11. FOOT SELECTION
Touch selection should consider:
- preferred foot;
- which foot is physically available;
- ball side relative to player;
- movement direction;
- upcoming plant;
- requested turn;
- action urgency.
Preferred foot should matter but must not cause impossible footwork.
A player should use the other foot when geometry/stride demands it.
12. CONTACT REGION
Support a small useful boot-contact vocabulary.
At minimum investigate:
- inside;
- outside;
- instep/front;
as appropriate for dribbling.
Do not build the entire kick-family library again.
We need enough variation to:
- push forward;
- guide laterally;
- take ball through a cut.
13. THE FOOT SHOULD MEET THE BALL
TURN-1.2 already exposes predicted foot motion.
Use that.
If a deliberate touch is selected:
- choose an appropriate upcoming foot;
- choose a feasible boot contact region;
- make a bounded swing adjustment;
- bring that boot region through the intended physical contact point.
Do not move the planted foot.
Do not distort the whole locomotion cycle merely to save a bad touch.
14. FREE-LEG SWING ADJUSTMENT
The ideal first implementation is similar to the previously identified concept:
touch adjustment is primarily a free-leg swing adjustment.

Keep:
- lift-off;
- landing;
- plant positions
stable.
Modify the swing trajectory within reasonable bounds so the boot meets the ball.
If the ball is not reachable within those bounds:
do not fake the contact.
The player may need another step.
15. ATTRIBUTES
Integrate the existing player attributes where appropriate.
Do not create direct attribute boosts to physics.
Relevant attributes should influence resolved touch quality, for example:
- Dribbling;
- Ball Control;
- Agility;
- Balance;
- Reactions;
- preferred foot / weak foot where applicable.
Use the repository's actual attribute definitions.
Do not invent duplicates if equivalent attributes already exist.
16. WHAT ATTRIBUTES SHOULD AFFECT
Attributes may affect:
- touch-distance accuracy;
- directional accuracy;
- timing/execution error;
- ability to use tighter touches at speed;
- feasible swing adjustment;
- weak-foot quality;
- recovery from imperfect touches.
They should NOT:
- change turf friction;
- magnetize the ball;
- disable physical collisions;
- directly steer a free ball.
17. SEEDED EXECUTION VARIATION
Preserve deterministic seeded randomness.
Touch error should be:
- seeded;
- auditable;
- localized to the touch event.
Prefer keyed/child RNG so unrelated changes do not reshuffle all future dribble touches.
Same seed + same state = same result.
18. BALL SEPARATION IS A FEATURE
Do not be afraid to let the ball visibly leave the player.
Particularly at RUN/SPRINT:
the player should sometimes have metres of separation from the ball between touches.

That's how the physical system becomes meaningful.
The player then catches up for the next touch.
19. THE BALL MUST BE STEALABLE
Even without implementing a defender AI system yet, prove that:
- another physical leg/body can intercept the ball between touches;
- the ball does not ignore collisions because it belongs to the dribbler;
- once knocked away, no possession controller snaps it back.
Build at least one interception fixture.
20. GENTLE CURVED DRIBBLING
After straight locomotion works:
test gentle TURN-1.2 curves.
The player should be able to guide the ball around the arc using natural touches.
Do not trigger dramatic cut touches for gentle steering.
21. 45–60° CUT
Next test:
RUN → 45–60° cut.
A useful sequence may be:
touch toward/into the future path
→ plant/cut
→ accelerate
→ next touch.
Use the actual TURN-1.2 plant geometry.
22. 90° SIDE-STEP CUT — HERO TURN CASE
This should be the primary change-of-direction dribble test.
Target broad sequence:
approach with ball
→ touch before the decisive plant
→ TURN-1.2 side-step plant
→ body changes direction
→ touch out into the new direction from the first feasible outgoing step
→ accelerate after ball.
Do not move TURN-1.2's plant to fit the ball.
Make the touch schedule work around the locomotion.
23. >90° TURNS
TURN-1.2 now has speed-dependent:
- ordinary TURN-1 pivots at lower momentum;
- brake;
- shuffle/reorganization;
- turn;
- acceleration
for large high-speed changes.
Dribbling must eventually support this.
But do not begin there.
Once straight / gentle / 45–60 / 90° work, test:
RUN 135°
and:
SPRINT 180°.
24. LARGE REVERSAL WITH BALL
A high-speed 180° reversal should NOT magically reverse the physical ball.
Investigate plausible behavior such as:
control touch / ball braking
→ player brakes
→ shuffle/reorganize
→ turn
→ exit touch
→ accelerate.
It is acceptable if this is only PARTIAL in DRIBBLE-1.
Do not destroy TURN-1.2 to solve it.
25. BALL CAN GET AWAY
Hard requirement.
If:
- touch is too strong;
- player changes direction badly;
- weak foot misexecutes;
- ball is intercepted;
- player cannot reach next contact;
the player can lose control.
Do not guarantee possession continuity.
26. DEFINE CONTROL STATE WITHOUT OWNERSHIP TETHER
We still need gameplay knowledge of who is plausibly controlling the ball.
Build a lightweight logical state such as:
- CONTROLLED / IN_DRIBBLE_ENVELOPE;
- LOOSE;
- CONTESTED;
or the repository's appropriate equivalent.
But this state must NOT physically attach the ball.
It is a gameplay classification, not a constraint.
27. CONTROL ENVELOPE
Control can consider:
- distance to ball;
- relative velocity;
- ball direction;
- predicted reachable foot contact;
- player orientation;
- opponent proximity.
If the ball exits the controllable envelope:
control is lost.
Do not drag the ball back inside it.
28. NO RAPID-FIRE TOUCHES
Prevent pathological:
tap-tap-tap-tap every few frames.
A deliberate touch should create useful separation before another deliberate touch is scheduled unless close-control context genuinely calls for it.
Use locomotion/foot opportunities rather than arbitrary cooldowns where possible.
29. DO NOT FORCE ALTERNATING FEET
Natural dribbling does not require:
LEFT → RIGHT → LEFT → RIGHT
forever.
If the same foot can naturally make consecutive touches across different strides, allow it.
Likewise allow alternating feet where geometry supports it.
30. BODY/ARM PRESENTATION
Do not build another locomotion body-language system.
TURN-1.2 is frozen.
The upper body should remain TURN-1.2 except for minimal bounded changes genuinely necessary for a touch.
Focus this mission on:
feet + ball.
31. TOUCH ANIMATION CONTACT MUST MATCH AUTHORITATIVE CONTACT
For every deliberate touch record:
- authoritative contact tick;
- boot;
- boot region;
- ball position;
- ball pre-contact velocity;
- resolved desired launch;
- ball post-contact velocity;
- angular velocity.
Visual foot/ball contact must align to that tick.
Do not let the animation visibly kick the ball before/after the authoritative event.
32. NO DOUBLE IMPULSE
If using resolved/hybrid touches:
ensure the physical boot collision does not apply an additional uncontrolled impulse on top of the authoritative deliberate touch.
Establish one clean handoff.
Afterward ordinary physical collisions resume.
33. INCIDENTAL CONTACT ALWAYS WINS AFTER HANDOFF
Once the deliberate touch has launched the ball:
- opponent foot;
- teammate;
- tackler;
- post;
- turf
can immediately alter it physically.
No touch controller should attempt to restore the planned trajectory.
34. DRIBBLING + TACKLE INTERACTION
If the current tackle work is available safely, build at least one fixture:
player dribbling → opponent slide/tackle contacts ball → ball becomes loose.
Do not integrate the entire tackle presentation system if that would expand scope.
The important test is that physical ball interruption works.
35. TOUCH TARGETS ARE NOT SCRIPTED BALL PATHS
The resolver may decide:
“I want approximately 1.4 m separation 10° right of travel.”

It may NOT prescribe:
“At t+100 ms ball is here; t+200 ms here; t+300 ms here.”

Resolve a launch.
Physics produces the path.

40. IMPORTANT VISUAL FAILURE MODES
Reject:
- ball glued to foot;
- invisible tether;
- ball teleport;

41. DO NOT OVER-CORRECT THE BALL
If a touch produces slightly imperfect ball placement but the next stride can naturally recover:

Do not continuously optimize every touch into a perfect dribble lane.
42. PLAYER SKILL SHOULD BECOME VISIBLE

PRIMARY DIRECTIVE
TURN-1.2 now gives us the feet and BALL-PHYS gives us a genuinely physical football. Combine them. Build dribbling as a sequence of deliberate, simulation-resolved foot contacts separated by genuinely free physical ball motion. The ball must leave the foot, travel over the turf, slow and collide normally, while the athlete uses real stride/foot opportunities to catch it and touch it again. No tether, no possession magnet, no scripted ball path. Prioritize straight running, gentle steering, 45–60° cuts and a convincing 90° cut. Make it responsive and fun, then stop for visual review.
